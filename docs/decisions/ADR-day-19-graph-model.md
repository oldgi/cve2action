# ADR-day-19：攻擊圖的節點與邊，以及觀測如何變成資產

- 狀態：Accepted
- 日期：2026-10-03
- 影響：新增 `src/cve2action/attack_graph/`（`resolve`、`model`、`build`）、CLI `cve2action graph`
- 相關：藍圖 §9.0 閘門 1、§10 Day 19、§15（節點類型不得超過六種）、§5 成功標準 #2 #10

## 背景

評分階段把每一筆 finding 當成獨立的一列。攻擊者不是這樣走的——他們從一個入口進來，踩過幾台機器，到達真正想要的東西。要表達這件事就需要圖。

但在畫圖之前有一個更基本的問題：**圖上的一個點，是什麼？**

弱掃回報的是 IP 或 hostname，不是資產。一台有三個介面的機器會被回報三次，同一個漏洞就產生三項修補工作——這正是成功標準 #10 要防的事。節點定義不能跳過歸併；**歸併就是節點定義本身**。

## 決策

### 1. 解析觀測的三態，與它們各自的下一步

`resolve(observation) → RESOLVED / AMBIGUOUS / UNKNOWN`

| 狀態 | 意思 | 要去做什麼 |
|---|---|---|
| `RESOLVED` | 恰好對到一台 | 正常進圖 |
| `AMBIGUOUS` | 對到多台 | 查這個位址背後是誰（例如 VIP 指向哪一台） |
| `UNKNOWN` | 對不到任何一台 | 查為什麼有機器不在清冊上 |

後兩者都不進圖，但**理由不同就不能寫成同一句話**。把兩者混成「找不到資產」，看不出該找誰。這與 Day 10 的 KEV 三態、Day 15 的控制適用性是同一條紀律。

### 2. 解析順序 MAC → hostname → IP，且不得往下遞補

資料本身證明了單一識別子不夠：

- **IP 不夠**：VIP `203.0.113.10` 被兩台入口網站同時宣稱。照 IP 併，兩台變一台。
- **hostname 不夠**：同一張網卡掛多個名字（`lab-wiki` 與 `wiki-old` 是同一台）。照 hostname 併，一台被拆成兩台。

順序照「愈不容易共用的愈優先」：MAC 綁在網卡上，hostname 可以是別名但仍指向一台，IP 最容易共用。

**關鍵規則：第一個對到東西的識別子就決定答案，即使它對到的是多台。** 不得因為 IP 對到兩台就改用別的識別子「試到單一答案為止」——那會讓 VIP 悄悄被歸給其中一台，而且不留痕跡。有回歸測試守著這條。

### 3. 四種節點、四種邊，Crown Jewel 不是節點

藍圖 §15 把「節點類型超過六種」列為攻擊圖失控的徵兆，要求只留資產、服務、帳號、Crown Jewel。我們用了**三種加一個虛擬入口**：

| 節點 | 代表 |
|---|---|
| `internet` | 外部起點。虛擬節點，不是資產。 |
| `asset` | 一台機器——歸併後的結果，不是一個 IP。 |
| `service` | 某台機器某個 port 上在聽的東西。**攻擊面是服務，不是主機。** |
| `account` | 一個帳號。它讓攻擊者從一台走到另一台。 |

**Crown Jewel 做成資產的旗標，不做成節點。** 做成節點就要多一種邊，而那條邊不帶任何新資訊——jewel 就是那台資產本身。少一種節點，就少一種之後每天都要維護的東西。這比藍圖的四種更保守，沒有違反 §15。

邊也是四種，各自對應一份可查證的資料：`hosts`（asset→service，來自 services.csv）、`reaches`（internet/asset→service，來自 network_edges.csv，帶 port）、`uses`（asset→account）、`grants`（account→asset，帶 privilege）。

帳號做成節點而非邊上的標籤，是為了 Day 24：共用帳號本身就可能是瓶頸，它得是個可以被指著的東西。

### 4. 被排除的邊不會消失

建圖時會丟掉三種連線，每一種都記在 `graph.excluded` 並附理由：政策拒絕的、指向沒有服務在聽的 port 的、指向 `filtered`／`closed` 服務的。

**Day 22 要回答「為什麼這台沒有路徑」。** 靜靜丟掉，就只剩「查無路徑」這種什麼都沒說的答案——而「查無路徑」和「證明不可達」是兩件完全不同的事（藍圖 §16 Day 24 門檻：無法到達的資產不會被誤標為可達，反之亦然）。

`filtered` 的服務**保留節點但沒有 `reaches` 邊**：服務還在（該修補），只是打不到（不構成路徑）。兩件事不能混成一件。

## 後果

- Northstar 建出 58 個節點（1 internet／20 asset／28 service／9 account）、72 條邊（28 hosts／24 reaches／10 uses／10 grants），排除 1 條（LAB→CORP 政策拒絕）。30 個介面併成 20 台資產。
- 新增 22 個測試；`cve2action graph` 可輸出 JSON 或解析單一觀測。
- 順手修掉一個 Day 11 留下的測試隱患：「重建逐位元組相同」那條測試原本會**實際改寫版控裡的資料檔**，與其他正在讀同一批檔的測試偶發干擾（這次真的紅了一次）。改為建到暫存目錄再與版控比對——不改寫工作區，而且驗證強度不變。
- 尚未做到：`reaches` 目前只看「政策允許且有服務在聽」，還沒看方向與回應路徑（Day 20）；路徑搜尋與長度（Day 22）；路徑進入分數（Day 23）。
