# ADR-0002：風險評分前必須通過資料與情境閘門

- 狀態：Accepted
- 日期：2026-09-15
- 決策者：Tsai Lisp

## 背景

企業弱掃結果常出現以下情況：同一設備的多個 IP 被視為多項資產、掃描器無法確認漏洞生效的精確子版本、不同網路區域被用相同方式評估、Port 或 Service 已關閉、ACL 僅允許正向清單，以及漏洞雖存在但缺乏可成立的攻擊路徑。

若將原始 Finding 直接送入加權公式，系統會精確地計算出一個建立在錯誤資產、錯誤適用性或錯誤可達性上的分數。

## 決策

每筆掃描觀測在進入 CRPS 前，必須依序通過：

1. **資產歸併**：將 IP、Hostname、MAC、Virtual IP 與管理介面解析到穩定的 `asset_id`。
2. **漏洞適用性**：依版本、Build、Package Release、Backport、模組與設定證據，標示 `CONFIRMED`、`LIKELY`、`UNKNOWN` 或 `NOT_APPLICABLE`。
3. **有效可達性**：結合 Zone、Service 狀態、Port、ACL、帳號狀態與既有控制，判斷可能的攻擊來源是否能抵達。
4. **攻擊路徑條件**：確認網路、帳號、權限及後續節點的前置條件是否能串成有效路徑。
5. **修補優先評分**：只有完成前述處理的 Finding 才計算 CRPS；資料不足者標示 `REVIEW_REQUIRED`。

## 資料處理原則

- 重複掃描觀測可合併成一項修補工作，但不得刪除原始觀測證據。
- `NOT_APPLICABLE` 不進入修補排序，但保留判定理由與證據。
- `UNKNOWN` 不得轉換成零分或低風險。
- Port 關閉、ACL、帳號回收等控制必須記錄驗證時間與有效範圍。
- 無外部路徑會降低優先度，但不能把風險直接歸零，仍須考慮內部及已受控節點情境。

## 後果

系統複雜度增加，但可避免重複工單、誤判漏洞存在與對不可達服務過度排序。模擬資料集與測試必須涵蓋多介面資產、無法辨識子版本、正向列表 ACL、已關閉服務及無法成立的攻擊鏈。
