# ADR-day-18（二）：對外用 P0–P3，內部維持 0–10；CRPS 乘法模型延後

- 狀態：Accepted
- 日期：2026-10-03
- 影響：`risk_rules.yaml` 的 `priority_bands` 新增 `tier` 與 `action`；輸出新增 `priority_tier`
- 相關：藍圖 [§3 產品主張](../../CVE2Action-30天總體施工藍圖.md)、§9.5 最終分數、§9.6 規則覆寫、[ADR-day-05](ADR-day-05-decision-engine-v01.md)、[ADR-day-18](ADR-day-18-scoring-acceptance.md)

## 背景

藍圖的終局是 **CRPS**：

```text
CRPS = 100 × L^0.45 × I^0.35 × max(A, 0.05)^0.20 × (1 − 0.6C)    範圍 0–100
P0 80–100 / P1 60–79 / P2 35–59 / P3 0–34
```

我們實際做出來的是 §9.6 授權的 v0.1 baseline：**0–10 的加法分數**，分級 Critical／High／Medium／Low。這個簡化從 Day 5 起就是明文允許的，不是偏離。

問題在銜接：**30 天施工表裡沒有任何一天負責「切換到 CRPS」。** Day 23「路徑條件進入分數」是 `A` 進場的時刻，也是最後一次能自然切換的機會。如果那天只是把 `A` 加成第五個加法項，就等於默默放棄 §3、§4.1 的 P0–P3、§5 成功標準第 5 條、§9.5，以及 §9.6 整套用 P0/P1 語彙寫成的覆寫規則。

## 決策

**對外以 P0–P3 呈現，內部維持 0–10 的加法分數；CRPS 的乘法形式延後，不在 30 天內實作。**

### 1. 分級帶上 tier 與 action

```yaml
- { label: Critical, tier: P0, floor: 9.0, ceiling: 10.0, action: 緊急評估與處理 }
- { label: High,     tier: P1, floor: 7.0, ceiling: 8.99, action: 納入下一個修補窗口 }
- { label: Medium,   tier: P2, floor: 4.0, ceiling: 6.99, action: 排程處理或補強控制 }
- { label: Low,      tier: P3, floor: 0.0, ceiling: 3.99, action: 監控、接受或定期複核 }
```

`label` 是內部刻度的名稱，Day 5 以來所有回歸基準都用它，一個字不動。`tier` 是對外的處置層級，語彙與 §9.5 一致——這讓 §9.6 的覆寫規則（「KEV ＋ Internet 可達 ＋ 有效路徑 → 至少 P0」）在 Day 22 之後寫得出來，不必再翻譯一次。

輸出新增 `priority_tier` 欄；載入時強制每個 band 都要有唯一的 tier。

### 2. 不採用藍圖的 80/60/35 門檻

這是本 ADR 最需要證據的一條。把 0–10 分數乘以 10 之後套用藍圖門檻，實測結果：

| 門檻 | P0 | P1 | P2 | P3 | 最大級佔比 |
|---|---:|---:|---:|---:|---:|
| 藍圖 80/60/35 | **21** | 16 | 1 | 0 | 0.5526 |
| 沿用 90/70/40 | 9 | 24 | 5 | 0 | 0.6316 |

藍圖門檻在 `band_balance` 這個指標上**比較好看**（0.55 對 0.63），但 38 筆裡有 21 筆 P0——而 P0 的定義是「緊急評估與處理」。**21 件緊急等於沒有緊急。** 指標衡量的是集中度，不是可行動性；這裡指標會騙人。

根本原因與 [ADR-day-18](ADR-day-18-scoring-acceptance.md) 的 structural／empirical 之分是同一件事：**門檻與公式是一對。** 80/60/35 是為乘法模型訂的，乘法會把分數拉得很開；加法分數結構上有地板（實測落在 56–100 的 0–100 刻度上）。只搬門檻不搬公式，就會壞掉。

這個量測結果有回歸測試釘住（`test_blueprint_thresholds_are_deliberately_not_adopted`），免得之後有人「順手對齊藍圖」而不知道代價。

### 3. CRPS 延後，而非放棄——但理由要說對

先更正本 ADR 初稿裡一個過簡的說法。`CRPS` 的指數加起來是 1（0.45＋0.35＋0.20），
所以它不是「乘法」，是**加權幾何平均**；真正的對比是算術平均 vs 幾何平均。
而且藍圖自己寫了 `max(A, 0.05)`，夾住之後 `0.05^0.2 = 0.549`，沒有路徑最多扣 45%
——它從未實作「一票否決」。初稿把差別說成「否決 vs 扣分」，那是錯的：差的是幅度。

真正在種類上的差別是**對不平衡的懲罰**：

| 四項因子 | 算術 | 幾何 |
|---|---:|---:|
| 0.8 / 0.8 / 0.8 / 0.8 | 8.00 | 8.00 |
| 1.0 / 1.0 / 0.1 / 1.0 | 7.75 | 5.62 |

幾何平均要求每一項都「有點成立」；算術平均接受「夠多項夠強就行」。

**延後的真正理由是尺度型別，不是公式品質。** 幾何平均要求因子是比例尺度
（比值有意義、有真正的零點）。我們的過不了這關：`B = NORMAL = 0.4` 指的是
「一般重要」這個等級，不是「衝擊是 CRITICAL 的四成」——那個 0.4 是訂來當地板的，
不是量出來的。相加對序數只假設間距相等；開次方則讓比值直接決定結果。

這個主張是可否證的：若 `B` 改成從受影響記錄筆數或每小時營收推導，幾何平均就重新站得住。

次要理由：`A` 要到 Day 22 才存在，現在換就得先補一個假的。

**也要幫它講句公道話。** `max(A, 0.05)` 有另一種讀法——`A = 0` 是「已證明無路徑」
真的歸零，`0.05` 是「查不到路徑」只夾不殺。若是這個意思，它編碼的正是本專案一路在守的
紀律：事實與未知要分開。目前無法分辨是哪一種，因為 `A` 還不存在。

### 4. Day 23 是決策日，不是順手多加一項的日子

不用辯論解決。Day 23 **兩種公式都實作**，對同一份輸入各跑一次，用 Day 17 的
`cve2action calibrate` 比 Kendall tau 與分歧清單；Day 18 的 `acceptance` 八條門檻
也各量一次。選擇的依據是這兩組輸出，不是哪個公式比較優雅。

這同時會檢驗上面那個「尺度型別」的主張——如果幾何平均在校準上明顯較好，
那就是我判斷錯了，照資料走。

延後的代價要寫清楚：**成功標準第 5 條「同時呈現 CVSS 排名與 CRPS 排名」在目前設計下是
「CVSS 排名 vs Priority Score 排名」。** 這一條需要在 Day 28 的 Dashboard 一併處理，
或修改藍圖措辭。

## 替代方案

- **Day 23 全面切換到 CRPS**：最忠於藍圖，但要重算十八天的基準，且 `L`／`I` 的子因子
  （§9.1 的 `E_CVSS`、§9.2 的 `B_CIA`、`B_Blast`）沒有資料來源。**此案未被否決，
  只是改為在 Day 23 以校準結果決定**（見決策 §4）。
- **把加法當成最終答案**：本 ADR 不採此案。加法與幾何平均都只是眾多可能形式的其中兩種，
  把其中一種宣告為終點，等於把「公式會隨輸入品質演化」這件事關掉。
- **明確放棄 P0–P3 語彙**：省事，但 §9.6 的覆寫規則、§14 展示腳本全都用這套語彙寫的，等於同時放棄那幾節。
- **只把分數乘以 10 當成 CRPS 對外呈現**：會讓讀者以為我們實作了 §9.5 的公式。叫它 CRPS 而它不是 CRPS，是更壞的選擇——所以輸出欄位叫 `priority_tier`，不叫 `crps`。

## 後果

- 輸出新增 `priority_tier`；`ranked_result` 契約進版至 1.3.0。
- 新增 4 個測試：tier 唯一且有 action、tier 與 label 永遠同步、缺 tier 拒絕載入、藍圖門檻的代價被釘住。
- 所有既有數字不變——這是純粹的對外命名層，9 筆 Critical 就是 9 筆 P0。
- **Day 23 正式成為決策日**，寫入藍圖 §10 該列的驗收重點；判準是 calibrate 與 acceptance 的輸出。
- 本 ADR 初稿把兩者的差別寫成「否決 vs 扣分」，那是錯的（藍圖自己夾在 0.05，最多扣 45%）。
  正確的差別是對不平衡的懲罰，而延後的理由是尺度型別。文章與本文均已更正。
- 公式選擇的脈絡——為什麼會有兩種、還有哪些第三種、以及公式如何隨輸入演化——
  另以番外篇說明，不塞進當日文章。
