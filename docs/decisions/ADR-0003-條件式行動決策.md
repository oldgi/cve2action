# ADR-0003：以條件式行動補足修補排序

- 日期：2026-09-16
- 狀態：採用為設計方向；尚待後續實作
- 觸發：Day 2 使用者修訂的資產與 finding 案例

## 背景

純排序無法表示相容性尚待驗證、風險接受尚未批准或補償性控制即將過期。把這些限制換成低分，容易讓系統誤認「已安全」或「已結案」。

## 決策

1. 保留分數作為輸入／解釋，另輸出行動、責任、期限、狀態與重評觸發條件。
2. 分開修補與緩解期限。緩解完成不能自動關閉修補工作。
3. 風險接受的單號、核准狀態、核准者與有效期分開保存；缺少必要證據不得默認放行。
4. 路徑以範圍、方向及條件表達。依賴共用來源的案件，在來源狀態變更時重新評估。
5. 利用、針對性與掃描活動分成不同證據欄位，未知值明確保留。

## 替代方案及取捨

維持單一分數最容易展示，但會藏掉未決條件。直接建完整工單與核准系統成本過高，因此 MVP 先保存可匯出、可檢查的決策狀態，不新增企業工作流平台。

## 影響

需擴充資料契約、驗證與 Demo；不在本次變更中修改 CRPS 權重。Day 2 靜態資料只展示狀態，不代表後續引擎已完成。
